# Backpropagation and gradient descent

## Training with backpropagation
Training starts with **random weights and biases**, so the first prediction is poor. In the **forward pass**, each neuron takes its weighted inputs plus bias, called the net input, and applies the **logistic activation function** to get its output. The hidden layer's outputs feed the output layer, and the output layer gives the prediction. The forward pass changes no weights.

The **cost function** combines the errors of the output neurons into one **total error**. In the worked example the two outputs predict about 0.75 and 0.77 against targets of 0.01 and 0.99, so the error is large.

**Backpropagation** sends this error back through the network. For each weight it works out the **partial derivative** of the total error with respect to that weight, which says how much a small change in the weight would change the error. A weight does not touch the error directly. It changes its neuron's net input, which changes the neuron's output, which changes the error. The **chain rule** multiplies these three links, so one hard question becomes three easy ones.

**Gradient descent** then updates each weight. It subtracts the gradient times the **learning rate** from the current weight, moving it in the direction that lowers the error. The worked example uses a learning rate of 0.5. The same process updates every weight and bias in every layer, and the cycle repeats over epochs until the error reaches the desired accuracy or the maximum number of epochs is reached.

> The forward pass makes a prediction. Backpropagation finds the gradients. Gradient descent changes the weights.

## Why backpropagation is needed
The error is measured only at the output, but every layer's weights affect it. Backpropagation passes the error back systematically so earlier layers can be corrected too. Without it only the last layer could learn.

## The learning rate
The learning rate sets the size of each update step and is chosen before training. A rate that is too large makes steps overshoot the minimum, so the error bounces up and down and training is unstable. A rate that is too small makes learning very slow. A good rate lets the error fall steadily.

> If the error bounces, lower the learning rate. Setting it to zero would stop learning altogether.
